# Battery Manager

Application for managing devices and their batteries. Consists of a FastAPI backend, Next.js frontend, and PostgreSQL database.

---

## Architecture

```
┌─────────────────┐      ┌─────────────────┐      ┌─────────────────┐
│   Browser       │──────│  Next.js        │──────│  FastAPI        │
│   localhost:3000│      │  frontend:3000  │      │  backend:8000   │
└─────────────────┘      └─────────────────┘      └─────────────────┘
                              │                           │
                              │      Docker Network       │
                              └───────────────────────────┘
                                                          │
                                                   ┌──────┴──────┐
                                                   │  PostgreSQL │
                                                   │  postgres   │
                                                   └─────────────┘
```

### Technology Stack

| Component | Technology | Port |
|-----------|-----------|------|
| Frontend | Next.js 24 Alpine | 3000 |
| Backend | FastAPI + Uvicorn | 8000 |
| Database | PostgreSQL 18 Alpine | 5432 |
| Migrations | Alembic | — |
| API Client | fetch (isomorphic) | — |

## Quick Start

### Prerequisites

- Docker + Docker Compose
- Git (optional)

### Launch

```bash
# 1. Clone the repository
git clone https://github.com/Hazardooo/battery-manager-app.git
cd battery-manager

# 2. Ensure .env is correct
# See the "Configuration" section

# 3. Start all services
docker compose up --build

# 4. Apply migrations (first launch)
docker compose --profile tools run --rm migrate

# 5. Open the application
# Frontend: http://localhost:3000
# API Docs: http://localhost:8000/docs
```

### Shutdown

```bash
docker compose down          # stop
docker compose down -v       # stop + remove volumes
```

## Configuration

The `.env` file in the project root:

```env
# Database Credentials
DB_USER=battarey_manager_admin
DB_PASSWORD=battarey_manager_pass
DB_NAME=battarey_manager
DB_PORT=5432

# FastAPI settings
APP_PORT=8000
APP_NAME="Battary Manager"

# For browser (client-side JS)
NEXT_PUBLIC_API_URL="http://localhost:8000"

# For server Next.js (inside Docker)
API_URL="http://backend:8000"

# NextJs settings
NEXTJS_PORT=3000
```

### Why Two API URLs

| Context | Variable | Value | Reason |
|---------|----------|-------|--------|
| **Browser** | `NEXT_PUBLIC_API_URL` | `http://localhost:8000` | Browser runs on the host machine, backend is exposed at `localhost:8000` |
| **Server Component** | `API_URL` | `http://backend:8000` | Inside the Docker network, `backend` resolves to the container's IP |

`NEXT_PUBLIC_` is a Next.js prefix; variables with it are embedded into client JS at build time. `API_URL` is only available in Next.js server-side code.

## Docker Compose

### Services

```yaml
services:
  postgres    # PostgreSQL 18 Alpine
  migrate     # Alembic migrations (profile: tools)
  backend     # FastAPI + Uvicorn + auto-reload
  frontend    # Next.js dev server
```

### Exposed Ports

| Service | Inside Container | On Host |
|---------|-----------------|---------|
| PostgreSQL | 5432 | `${DB_PORT:-5432}` |
| FastAPI | 8000 | `${APP_PORT:-8000}` |
| Next.js | 3000 | `${NEXTJS_PORT:-3000}` |

### Volumes

| Service | Mount | Purpose |
|---------|-------|---------|
| PostgreSQL | `postgres_data:/var/lib/postgresql/data` | Data persistence |
| Backend | `./backend/src:/app/src` | Hot-reload code |
| Frontend | `./frontend:/src/app` | Hot-reload code |

### Healthcheck

PostgreSQL is checked via `pg_isready` every 10 seconds. Backend and migrate start only after the healthcheck succeeds.

## API

### Base URL

- Local: `http://localhost:8000`
- Inside Docker: `http://backend:8000`

### Endpoints

| Method | Path | Description | Request Body |
|--------|------|-------------|------------|
| `POST` | `/create` | Create device | `DeviceBaseSchema` |

## Frontend

### API Layer Structure

```
frontend/src/features/devices/api/
├── client.ts        # Base HTTP client
├── getDevices.ts    # GET /devices
├── createDevice.ts  # POST /create
├── updateDevice.ts  # POST /devices/{id}
├── deleteDevice.ts  # DELETE /devices/{id}
└── index.ts         # Barrel exports
```

### HTTP Client (`client.ts`)

```typescript
const API_URL = typeof window === 'undefined'
  ? (process.env.API_URL || "http://backend:8000")      // Server Component
  : (process.env.NEXT_PUBLIC_API_URL || "http://localhost:8000"); // Browser
```

The client automatically picks the correct URL depending on the execution context:
- **Server Component** (`typeof window === 'undefined'`): uses `API_URL` to reach the backend inside the Docker network
- **Browser**: uses `NEXT_PUBLIC_API_URL` to reach the exposed port

### Error Handling

On HTTP errors, the client throws an `ApiError`:
```typescript
class ApiError {
  status: number;      // HTTP status
  code: string;        // error || "UNKNOWN"
  message: string;     // message || statusText
}
```

### Usage Examples

```typescript
import { getDevices, createDevice, updateDevice, deleteDevice } from "@/features/devices/api";

// Get all devices
const devices = await getDevices();

// Create a device
const newDevice = await createDevice({
  device_name: "Flashlight",
  battery_type: "AA",
  battery_count: 2
});

// Update a device
const updated = await updateDevice(id, {
  device_name: "Flashlight Pro",
  battery_type: "AA",
  battery_count: 4
});

// Delete a device
await deleteDevice(id);
```

## Troubleshooting

### `NetworkError when attempting to fetch resource`

**Cause**: `NEXT_PUBLIC_API_URL` points to `http://backend:8000`, but the browser cannot resolve Docker service names.

**Fix**: Ensure `.env` contains:
```env
NEXT_PUBLIC_API_URL="http://localhost:8000"
API_URL="http://backend:8000"
```

And rebuild the frontend: `docker compose up --build frontend`

### `fetch failed` in Server Component

**Cause**: The Server Component runs inside the `frontend` container, where `localhost:8000` is the container itself, not the backend.

**Fix**: Add `API_URL="http://backend:8000"` and use it in `client.ts` for the server context.

### CORS Error

**Cause**: The frontend domain/port is not listed in FastAPI's `allow_origins`.

**Fix**: Add the required origin in `main.py`:
```python
allow_origins=[
    "http://localhost:3000",
    "http://127.0.0.1:3000",
    "http://localhost:8000",
]
```

### Migrations Not Applied

**Cause**: The backend started before PostgreSQL was ready.

**Fix**: Ensure `depends_on` with `condition: service_healthy` is working. Or apply manually:
```bash
docker compose --profile tools run --rm migrate
```
